Overview

Custom mod cards allow mod authors to create downloadable, installable mod packages that integrate directly with GPU Selector. Users can load multiple cards simultaneously from URLs or local files, and each card appears in the Mods tab with its own download, install, and launch capabilities.

Key Features:
  • Automatic download with AMSI malware scanning
  • ZIP extraction to safe locations
  • Game targeting: link your mod to specific games from the user's library
  • Custom UI elements (dropdowns, radio buttons, checkboxes, text inputs)
  • Update checking from source URL
  • Custom button colors and branding
  • Open folder button to access mod files
  • Searchable: users can find your card by mod name or game name
  • Multi-card: load multiple cards at once, each with independent state
  • Organizer cards: cards with empty versions can highlight and group games without downloads

Multi-Card Support

GPU Selector supports loading multiple mod cards simultaneously. Each card operates independently with its own download state, install tracking, detection, and UI elements.

Card Name = Unique ID

The name field is the card's unique identifier. Two cards cannot share the same name. Card names cannot be renamed after creation: the backend uses the name to key mod folders, download tracking, and install manifests.

Important: Choose your card name carefully! Changing it later would orphan all downloaded files and install manifests. If you need a different name, create a new card.

Built-in Cards

Some cards are built into GPU Selector (e.g., Windower 4). Built-in cards are special:

  • Cannot be deleted by the user
  • No gear/manage icon: they are read-only
  • Auto-refresh from embedded constants on every app startup
  • Frozen at runtime (Object.freeze) to prevent accidental mutation

Locked Cards

Mod authors can set "locked": true in their card JSON to hide the View/Edit JSON option from the gear menu. This is useful for cards distributed to end users where you don't want them accidentally editing the raw JSON.

{
  "cardVersion": "1.0",
  "name": "My Mod",
  "locked": true,
  ...
}
Note: locked only hides the JSON editor from the UI. The card can still be deleted and re-added. It does not provide security: it's a convenience feature to reduce support requests from users who break their card JSON.

Organizer Cards (No Downloads)

Cards with an empty "versions": [] array are valid. These "organizer" cards highlight and group games from the user's library without offering any downloads. They're useful for:

  • Grouping games by franchise (e.g., "DOOM Games", "Souls Games")
  • Highlighting games that support a certain mod ecosystem
  • Creating a curated collection with custom button colors and branding
{
  "cardVersion": "1.0",
  "name": "DOOM",
  "description": "Highlights your DOOM games",
  "tagline": "Rip and Tear",
  "versions": [],
  "targetGames": [
    {"match": "contains", "name": "DOOM"}
  ],
  "ui": {
    "buttonColor": "#b91c1c",
    "buttonHoverColor": "#991b1b"
  }
}

Per-Card State Isolation

All runtime state is isolated per card. Each card maintains its own:

  • Detected install path
  • Download/install progress and spam protection
  • Install state per game (installed/not installed)
  • Config file detection results
  • Matched games list

This means two cards can both target the same game without interfering with each other.

Play Button Behavior

The play button (▶) next to each game in a mod card uses the game's full launch settings from the Games tab: including GPU selection, monitor preferences, launch arguments, pre/post scripts, and all other per-game settings. It does not bypass any game configuration.

Where Cards Live: Custom Cards or Modding Tools

  1. Cards people add go to Custom Cards on the Mods tab.
  2. In the + Add Mod window, Put them in picks the place: Custom Cards (default) or Modding Tools.
  3. It works for all three ways to add a card: Load from URL, Load from File and Cards on the House.
  4. Load from URL takes a card (.json) or a card package (.zip or .7z).
  5. Move a card later: right-click it.
  6. Built-in wrappers (ReShade, DXVK, dgVoodoo, Zink) are in Modding Utilities.

Targeting Specific Games

The targetGames field lets you link your mod to specific games from the user's library. When a user has matching games installed, a scrollable game list appears on your card showing each matched game with per-game Install, Unload, and Play buttons.

How Game Matching Works

Each entry in targetGames supports several match types, from most precise to broadest:

"targetGames": [
  {"match": "exe_hash", "hash": "a1b2c3d4e5f6...64chars..."},
  {"match": "id", "name": "steam_379720"},
  {"match": "exact", "name": "DOOM", "store": "Steam"},
  {"match": "contains", "name": "DOOM"},
  {"match": "startsWith", "name": "DOOM"},
  {"match": "pattern", "name": "*Dark Souls*"}
]
Match TypeBehaviorExample
"exe_hash"Matches the SHA-256 hash of the game's executable (absolute precision)Targets one specific game binary, regardless of name or store
"id"Matches the game's unique internal ID"steam_379720" targets exactly one game
"exact"Game name must match exactly (case-insensitive)"DOOM" matches only "DOOM"
"contains"Game name must contain the word as a whole word (word-boundary)"DOOM" matches "DOOM Eternal" but not "GOSDOOMA"
"startsWith"Game name must start with the target string"DOOM" matches "DOOM" and "DOOM Eternal"
"pattern"Wildcard matching with * (broadest)"*Souls*" matches "Dark Souls III", etc.

Exe Hash Matching

The "exe_hash" match type uses a SHA-256 hash of the game's executable file for absolute precision targeting. This is the most reliable way to identify a specific game, especially for non-store games or custom executables where names and IDs may vary between users.

{"match": "exe_hash", "hash": "a1b2c3d4e5f6..."}
How to get a hash: Right-click any game card in the Game Library and select Extract Exe Hash. The SHA-256 hash of the game's executable will be copied to your clipboard, ready to paste into your mod card JSON.
Note: Exe hashes change when the game updates. If the game receives a patch that modifies its executable, the hash will no longer match. For games that update frequently, consider combining "exe_hash" with a name-based fallback like "contains".
Store Filter: Any name-based match type can include an optional "store" field to restrict matches to a specific store. For example: {"match": "exact", "name": "DOOM", "store": "Steam"} will only match DOOM from Steam, not from GOG or Epic.
Game IDs: IDs follow the format store_identifier (e.g., steam_379720, gog_123456, epic_DOOM). The "id" match type is useful when multiple games share the same name across different stores. For non-store games, use "exe_hash" or "exact" with "store": "Custom".
Search Integration: When your card specifies targetGames, users can find it by searching for game names in the search bar. For example, if your card targets "Elden Ring", typing "elden" in the search will show your card.

What the User Sees

When targetGames is defined:

  • A scrollable Target Games list appears showing matching games with per-game Install / Unload buttons
  • Each game shows a status dot (green = installed, gray = not installed)
  • A ▶ play button per game auto-installs (if needed) then launches
  • When more than 2 games match, a search box appears
  • A Clean All button removes mod files from all games at once
  • Install actions can use {game} to reference each game's folder

Per-Game Install Actions

Each target game entry can define its own installActions for game-specific files:

"targetGames": [
  {
    "match": "exact", "name": "FINAL FANTASY VII REMAKE",
    "installActions": [
      {"type": "copy", "from": "ff7r/dxgi.dll", "to": "{game}/dxgi.dll"}
    ],
    "skipDefaultActions": true,
    "logPatterns": ["*.log", "crash_*.txt"]
  },
  {"match": "contains", "name": "FINAL FANTASY"}
]
FieldDescription
installActionsArray of game-specific install actions (max 5). Appended to top-level installActions.
skipDefaultActionsIf true, skips the top-level installActions for this game (only uses per-game ones).
logPatternsArray of glob patterns for mod log files (max 10). Used for auto-cleanup on unload.
reshadeSuggested ReShade modes for this game: {"proxy": true, "opengl": "on", "vulkan": "off"}. Each game row has injection (Auto or Proxy), GL and VK buttons (the game's own settings); a suggestion that isn't set yet gets an amber dashed edge. Add "lock": true when you know the game's API: the modes are set for the user and locked on the card.
hdrtrue when the game needs Windows HDR (an HDR mod). When the user turns the card's add-on on for the game, its HDR box is ticked, so GPU Selector turns HDR on when it starts. It never unticks it.
notesUp to 8 short lines about this game, like settings it needs: ["Set Color Precision to High."]. The game's row gets a Notes button that opens them. Only people who have the game see them.

Unload & Cleanup

All files installed to game folders are tracked in an install manifest. Users can:

  • Unload a specific game: removes all tracked mod files from that game's folder
  • Clean All: removes mod files from all games at once
  • Clean logs: when checked, also deletes files matching logPatterns
Limit: A maximum of 25 target games per card is enforced. If you need to support all games, omit the targetGames field entirely.

Exe Launch Security

When launchExe is set, users see a security warning before the executable runs. This protects users from unexpected program launches. The warning shows the executable name and requires explicit confirmation.

Loading Your Card

Users can load cards in three ways:

  • URL: Paste a link to your JSON file in the + Add Mod dialog
  • File browser: Click "Browse" in the + Add Mod dialog
  • Drag & drop: Drag a .json file onto the + Add Mod button or empty state area

Security Confirmation

When users click Download, a security warning dialog appears showing the mod name, author, download URL, and source. Users must confirm before any file is downloaded. This protects users from unverified content.

Writing Card Text

Use \n for a new line in description. GPU Selector lays the text out for easy reading:

  1. The first line is a short lead, shown a little brighter.
  2. Lines that start with 1., 2. ... become numbered step boxes, like the 3DConsoleBridge card. They take the picked mode's color.
  3. A line that starts with spaces joins the line above it.
  4. An empty line adds space.

Keep it short: one idea per line, about 5 to 10 lines. Use tabs for more.

Style Guide

These cards follow these rules: SR Loom, Windower 4, 3DConsoleBridge, Neural Rendering and RenoDX HDR. Use them as your style examples, so every card feels the same.

The Card Feature Test card only tests features. It is not a style example.

Words

  1. Simple English. Short numbered lines, one idea per line. Many readers have dyslexia: no walls of text.
  2. No em dashes. Use a period, a colon or a new line.
  3. Never start a line with spaces: it joins the line above it.
  4. Only write what you found in the project's own docs, or what you tested. Not sure? Leave it out.
  5. Say what GPU Selector does for the user, and how: "GPU Selector sets X=3 for you, if it is not set yet."
  6. 3D projects: "turns your games into 3D". Never "real 3D".

The description, in this order

  1. What it needs: "Needs an NVIDIA RTX 20, 30, 40 or 50 card."
  2. Which games: "For 64-bit DirectX games WITHOUT a DLSS option."
  3. Which tab to pick, when there are several: "Not sure which tab? ..."
  4. What it installs, and that each part is needed.
  5. The steps, numbered (like effect order in ReShade).
  6. What GPU Selector sets for the user.

Tabs

  1. Use "position": "top" and short labels (one or two words).
  2. One tab per hardware or setup: NVIDIA | NVIDIA + DLSS | AMD.
  3. Or one tab per part of the card: HDR Mods | Setup | Game Notes, or About | Head Tracking | Keys.
  4. The first tab is the one people use most. The game list and the install button live there.
  5. Each tab must be different: its own text, games or button. Not the same tab twice with new words.
  6. Several topics? Give each one its own tab, like About | Use | Notes. Don't stack guides or one long list instead.

Where long text goes

  1. Notes for one game: that game's notes (its Notes button).
  2. A tab whose games are all on other tabs shows no game list. That is fine for Setup or Notes tabs.
  3. One-time setup: a Setup tab.
  4. Notes for every game: a Game Notes tab, or a guide with "position": "bottom".
  5. At most one short guide per tab. More to say? Use a tab.
  6. "notice": only for a real, important warning from the project's own docs. Never a notice you made up, like "made by AI" or "untested".
  7. A card may be up to 625 pixels tall. The game list shows about two games and scrolls.

Pictures and colors

  1. Icon: the project's own logo (from its repo or website), as a PNG about 128 pixels. Background: its wide logo or art, as a JPEG about 960 pixels wide.
  2. Never use a screenshot of the program as the background. No fitting art? Leave backgroundArt out.
  3. Never a company's logo (NVIDIA, AMD...) on someone else's project.
  4. No logo? Leave icon out. Keep the project's github (it opens the project page): when its owner has no picture, GPU Selector draws a name icon in the card's color. Leave github out only when the project has no repo.
  5. Colors come from the project's logo. Tabs, step numbers and the hover border use its main color. The button uses a darker shade, so its white text is easy to read.
  6. Not sure? Use "autoColor": true.
  7. Keep the whole card file small (under 1 MB is plenty).

Credits

  1. author (and each tab's author) is who made the project. Never yourself.
  2. cardBy and cardByUrl are you, the card maker. They show as "Card by" at the bottom right.
  3. A tab's github is the project that tab installs. Never another person's repo.

Games

  1. Each game twice in targetGames: its Steam ID ("match": "id") and its exact name (other stores).
  2. hdr: true for HDR mods. reshade locks only when you know the game's API.
  3. Leave out games the mod can't be used in safely (online-only games with anti-cheat), and say why in the notes.

Locked Cards (a key for your supporters)

Lock a card's download so only people with your key can install it, like your Patreon supporters or testers. You lock the file. GPU Selector only asks for the key.

How it works

  1. You lock your mod in a .7z file with a password (7-Zip, AES-256).
  2. You put the locked file online, anywhere: a GitHub release, your own site.
  3. Your card says the download is locked. It never holds the key.
  4. You give the key to your people however you like: a Patreon post, Discord, email.
  5. When someone downloads, GPU Selector asks for the key. It is used once to unpack the file, then forgotten. It is never saved, sent anywhere, or written in the log.

Create the locked file

With 7-Zip (free, 7-zip.org):

  1. Right-click your mod's files, pick 7-Zip, then Add to archive...
  2. Archive format: 7z.
  3. Enter password: your key. For "login" type username:password, like shrimp:shrimp.
  4. Encryption method: AES-256.
  5. Tick Encrypt file names, so nobody can even see what is inside.
  6. Press OK. Upload the .7z and put its link in your card.

Or on the command line: 7z a -t7z -mhe=on -p"shrimp:shrimp" ExampleMod.7z ExampleMod.fx

Keys can't have quotes in them. A new key means a new locked file: make one, upload it, and give out the new key.

What a key can and can't do
  1. Everyone with the key can unpack the file, and people can share keys. For one key per person you need your own server: the guide's example cards repository shows ideas.
  2. Anyone can read your card. Never write the real key in it.
  3. The lock is the file's own encryption. Without the key the file can't be opened, wherever it is hosted.
  4. Some sites refuse locked files: Nexus Mods quarantines password-protected archives. Use a GitHub release or your own site.

Example: the Locked Card Example in GPU Selector's example cards (cards/testing/locked-card-example). Its prize is Shrimp Vision, a small ReShade shader. Username shrimp, password shrimp.

Card Sites (log in to your own site)

Have your own website for your mods? A card can log in to it, show the files that user may get, and install them. You host the site. GPU Selector hosts nothing.

What the user sees

  1. A box with your site's name, a username, a password and Log In.
  2. After logging in: your files, each with its title, version, size, a short line and Download.
  3. Download gets the file, checks its SHA256, Windows Security scans it, and your card's installActions put it in place.
  4. Refresh asks your site again. Log Out forgets the login.

Mode Switch (one card, several setups)

A card can have a mode switch: a row of tabs under its name, like the 3D | AR | SR switch on the 3DConsoleBridge card.

  1. Each mode can have its own description.
  2. Controls, downloads and add-ons can belong to one mode with "when".
  3. Up to 4 modes show at once. With more, a small arrow button shows the next 4.
  4. 2 to 12 modes are allowed.
  5. "position": "top" (on ui.modes) puts the switch in the top right, next to the folder button (like 3DConsoleBridge). Use it for short tab names. Without it, the switch gets its own row.
  6. Give modes a "gpu" and the switch starts on the one for the user's graphics card.
  7. Add-ons that only come from tabs with a "gpu" belong to that brand. They only load in games that run on it (the GPU the game is pinned to, or the primary GPU). Users can install every tab, and each game gets the right add-on.
  8. Two tabs of the same brand (like "NVIDIA" and "NVIDIA + DLSS"): both can be installed, and the user ticks per game which add-on it uses. Say in each tab which games it is for.
  9. Add-ons on the same tab are a team: ticking one ticks the add-ons it needs. "Needs" means: the other add-on is on every tab this one is on. Example: dlss5-feed is only on the NVIDIA tab, where renodx-dlss5 also is, so it needs renodx-dlss5. renodx-dlss5 is also on the NVIDIA + DLSS tab, without the Feeder, so it needs nothing. An add-on with its own "games" is never part of a team.
  10. Each tab can have a Remove button: it removes that tab's add-ons, but keeps one another installed tab still uses.

Add-on Packages from GitHub

A card can download files from GitHub and add ReShade add-ons to GPU Selector. The card's button then says Install Add-ons.

  1. GPU Selector downloads every file the card lists.
  2. It checks each file with the SHA256 GitHub lists for it.
  3. Windows Security scans each file up to 50 MB. Bigger files are not scanned, but are still checked with their SHA256.
  4. Zip and 7z files are unpacked.
  5. The add-ons go into the user's add-on list (Manage Add-ons).
  6. The user picks the games: the card's own games, all games, or games they pick.
  7. The add-ons only run in those games, through ReShade Inject Mode.
The rules GPU Selector follows:
  1. Nothing is copied into a game folder for good. Add-ons are copied for each launch and removed after.
  2. A file Windows Security flags stops the whole install. GPU Selector never asks for exclusions or works around Windows Security.
  3. A file with no SHA256 is only downloaded after the user agrees.
  4. A card can't replace an add-on it did not install, or one of GPU Selector's own.
  5. Downloads must use https. Only download from where the project's author publishes the files (their GitHub releases, or a host their own installer uses). Never mirrors or re-uploads.
  6. Links that redirect are followed.

"downloads"

Up to 10. Each has an "id". Files of a download are unpacked into a folder with that id.

besideAddon or nextToGame? Read this before you follow a project's install guide.
  1. Most install guides say "put everything next to the game's exe". They assume the add-on sits there too.
  2. In GPU Selector the add-on sits in a launch folder, not next to the game.
  3. Files the add-on opens from its own folder: besideAddon. Example: DLSS5-Feeder starts NVIDIA NGX with its own folder, so it needs nvngx_dlss.dll and nvngx_dlssnr.dll beside it.
  4. Files the game, the graphics driver, or the add-on load from the game's exe folder: nextToGame. Example: RenoDX DLSS5 loads nvngx_dlssnr.dll from the game folder, and the AMD neural add-on its runtime and weights.

  6. Depth: GPU Selector always loads a depth add-on (Generic Depth or Generic Depth Mod). An add-on that needs ReShade's depth gets it without anything on the card.
  7. Unreal games: GPU Selector finds the exe that really runs (Binaries\Win64\*-Shipping.exe) and puts the files there.

"launch": a program the card downloads

For a tool or app (not an add-on), download it and give the card a Launch button:

"downloads": [{"id": "app", "github": "owner/repo", "asset": "MyTool.exe"}],
"launch": {"from": "app/MyTool.exe", "label": "Launch My Tool"}
  1. The button says Download, then Get Latest. A Launch button shows once it is downloaded.
  2. The program is checked and scanned like every download, and kept in the card's own folder.
  3. The first Launch each time GPU Selector runs asks the user first.
  4. A card can have launch and addons together, or only launch.
  5. Start options: "launch": {"from": "app/MyTool.exe", "args": ["--game", "quake"]}. Plain words only.
  6. from starts with a download's id: a card only launches a file from its own downloads. A helper you made yourself must be in a GitHub release first.
  7. One launch per card. Give it "when" to show it only on some tabs.
  8. "app/MyTool.exe" finds that name in any folder of the download. More than one? The one nearest the top wins. "app/bin/MyTool.exe" finds only that path.
  9. Zips keep their folders. Look inside the zip and read the app's docs, so the Launch button starts the right file (not a helper or a command-line tool that closes at once).
  10. Once it is downloaded, an Uninstall button shows next to Launch. It moves the card's download to the Recycle Bin, and the card shows Download again. Rename it with ui.labels.uninstall.
  11. A card package installs ReShade add-ons (.addon32 / .addon64) and programs with launch. Other mod files (like a game's .pak files) use a catalog card, or installActions.

"requires": the ReShade a card needs

"requires": {"reshade": "6.8.0"}
  1. Every card with add-ons needs ReShade with add-on support. GPU Selector checks that by itself.
  2. "reshade" also asks for that version or newer. Write it as three numbers, like "6.8.0". Use the version the project's install guide asks for.
  3. GPU Selector reads the ReShade card's version and build. When they don't fit, the card shows a warning and says what to change. The install dialog says it too.

Games with a ReShade preset: "match": "preset"

A shader card can list every game that has a ReShade preset, and help it get the shaders the preset needs:

"targetGames": [{"match": "preset"}],
"shaderRepos": ["CeeJayDK/SweetFX", "prod80/prod80-ReShade-Repository"]
  1. GPU Selector looks in each game's folder for presets: the one the game's ReShade.ini points to (PresetPath), and any other .ini that is a preset, whatever its name. A file is a preset when its top part has a Techniques= line.
  2. It reads which effect files (.fx) the preset turns on, and which of them no shader folder has (GPU Selector's, or the game's own reshade-shaders).
  3. The game's row shows Preset: name.ini (3 missing). Pressing it lists the missing effects, and which of the card's shaderRepos hold them.
  4. Install missing packs installs only those packs. Effects no pack holds are listed as "not in this card's packs".
  5. The card never downloads anything it has no link for. To cover more presets, add the shader packs' GitHub repos to shaderRepos (only packs whose authors allow it).

"shaderRepos": shaders from Shader Repositories

Need a shader pack? Don't download it yourself. List its GitHub repository (or a Shader Repositories key):

"shaderRepos": [
  "owner/some-shader-repo",
  {"repo": "owner/other-shader-repo", "when": {"setup": "nv"}}
]
  1. It installs exactly like pressing Install on that repo in Shader Repositories.
  2. Only list shaders whose authors allow it. Some ask that their shaders are not shared or linked by other tools.
  3. A GitHub repo that isn't in the list yet is added there first.
  4. The user can update or remove it there later, like any other shader repo.
  5. A card can have only shaderRepos, with no downloads.
  6. A full link works too: "https://github.com/owner/repo". The card shows each pack's result.

"repoShaders": only the shaders an add-on needs

Does your add-on need one effect from a built-in shader repo? Put this on the add-on instead of shaderRepos:

"repoShaders": {"repo": "lumenitefx", "files": ["lumenite_Kernel.fx"]}
  1. Only the listed effects come with the add-on, plus the headers and textures they use.
  2. They only load in games where the add-on is on.
  3. If the user installed the full repo from its own card, their copy is used, with all its effects.
  4. Built-in repos only, for now: lumenitefx. GPU Selector downloads it from its own link.
  5. One object per add-on. Two add-ons (or two cards) can ask for the same effect: it is shared.
  6. ReShade.fxh and ReShadeUI.fxh are always there. Don't ship them.

"preprocessor": shader settings the add-on needs

Does an effect need a preprocessor value set for your add-on? Put it on the add-on:

"preprocessor": {
  "lumenite_Kernel.fx": {"IMAGE_SPACE": "1"},
  "AMD_Neural_Feed.fx": {"AMDNR_MV_PROVIDER": "3"}
}
  1. At launch, GPU Selector writes them into that game's ReShade preset.
  2. Only in games where the add-on is on.
  3. Only when the value is not set yet. A value the user set stays.
  4. Plain names and values only (letters, numbers, _ . + -). Up to 10 effects, 10 values each.
  5. Find the values in the project's install guide. The example is the Neural Rendering card: AMDNR_MV_PROVIDER 3 means "LumeniteFX Kernel gives the motion", and Kernel's IMAGE_SPACE=1 makes it work from the color picture, with no depth needed. The card sets IMAGE_SPACE=1 on both the NVIDIA (DLSS5-Feeder) and the AMD tab: tested in games, it is needed on both.

  7. GPU Selector can't turn effects on or set their order. Write the order as numbered steps on the card.

What the user sees

  1. A warning that lists every download and where files go.
  2. Progress while it downloads, checks and unpacks.
  3. A question: which games should use the add-ons.
  4. The card then shows what is installed. The button changes to Reinstall Add-ons (gets the newest releases).
  5. A card with no target games: Games I Pick opens Manage Add-on Games.
  6. About every 12 hours the card checks GitHub. It says when a file it installed was rebuilt (same release, new file) or when a newer release of the same product exists.

Built-in protection

GPU Selector applies these to every card. A card can't turn them off.

  1. Every download is scanned by Windows Security, then its fingerprint (never the file) is checked against two known-malware lists (CIRCL hashlookup and Team Cymru). A file on a list is not installed.
  2. Check Updates: once every 5 minutes per card.
  3. A card update shows its new download links and add-ons before it replaces the card. A card can't change its name in an update.
  4. Install: one card at a time, and a 30 second rest after each install.
  5. One download: 2 GB at most. Unpacked: 8 GB and 20,000 files at most.
  6. A card file: 2 MB at most (pictures included). 40 custom cards at most.
  7. Text: name 60, description 1500, mode label 24 characters at most.
  8. GitHub allows 60 lookups an hour without an account. When they run out, the card says so.
  9. Card names: 1 to 60 characters, with a letter or number, and none of < > " ' ` \ &. A name can't collide with another card or a built-in one.
  10. Colors must be color codes like #10b981. Links and pictures must be clean https links or PNG/JPG data pictures.
  11. Lists: up to 20 dropdown options, 10 radio options, 20 versions, 25 target games. Labels and placeholders have length limits too.
  12. nextToGame can't hold programs: .exe .bat .cmd .com .scr .ps1 .vbs .js .msi .lnk .pif .hta .reg, or ReShade's own ReShade.ini and ReShadePreset.ini. DLLs are allowed. The install dialog names every file that goes next to the game and every program file.
  13. Add-on names GPU Selector keeps for its own add-ons: anything with gamebridge, srreshade, xinp, genericdepth, generic_depth, depth3dcursor or sd3dcursor in it.
  14. detection.configFiles may only read files inside the folder it detected.
  15. A card that breaks these rules is not shown, even if it was added before the rules existed.
  16. Every card update is confirmed and lists what changes, including new links, different files, a missing SHA256 or an older release.

Catalog Cards (a list of mods for any game)

A catalog card lists mods for a game. People install, mix and play them one by one. The DOOM card is the big example. Copy the parts you need.

  1. Add a "catalog" object to the card.
  2. Pick the engine:
    • "engine": "doom" (the default): DOOM-engine games. GPU Selector knows DOOM's game files (WADs), its ports and idgames.
    • "engine": "generic": any other game. You tell GPU Selector which game files to find, which file types are mods, and how to start the port (see Any game).
  3. The card gets these pages: Your Games, Engine Games, Mods and Options.
  4. Show them in the card's tab switch with ui.modes: values games, engine, mods, options, and "position": "top". Leave out a page you don't need.
  5. No ui.modes? The catalog draws its own tab row. Pick its tabs, order and names with "tabs": [{"id": "mods", "label": "Mods"}, {"id": "games"}], and where it sits with "tabsAlign": left, center or right (default).
  6. Hide a tab only if your card doesn't need it:
    • games has Look Again and Pick a File. Without it, people can't fix "Needs ..." on a mod.
    • options has 3D Settings and Reset 3D. Without it, the 3D button still works, with your stereo values.
  7. Number the tabs in setup order, like "1. Your Games". The card opens on the first one.
  8. Options has these sub cards, in this order (change it with "optionsOrder": ["ports", "stereo", "yours", "look"]):
    • 3D Settings (hide it with "options": {"stereo": false}; the colours of "3D" with "stereoTitleColors": ["#ef4444", "#3b82f6"], or false for plain text)
    • Your WADs and Add-ons: people add their own files or folders, and their own add-ons for the Mix view (the add-ons part only when Mix is on; the name follows the engine)
    • Source Ports
    • Parental, Theme and Font: Parental Settings (only when an item has "adult": true), and the theme and font (only when the card has ui.appTheme or ui.font)
  9. The card stays within 625 pixels. A long page or open sub card grows to that size, then scrolls inside itself.
  10. GPU Selector finds the game files, downloads the mods and builds the command line. The card only lists things.
  11. Ports come from the Modding Codex, or the user installs one ("own": true). The Codex shows "Used by" with your card's name.
  12. Play adds the mod to the Games list, so GPU Selector's settings work for it (GPU, Inject Mode, SuperDepth3D).
  13. A port with "stereo": true (GZDoom family) gets a 3D button on each mod: the 3D mode, Depth and ZPD come from 3D Settings.

Ports

  1. A port: {"id","name","codex","family"}. codex is the Codex entry's exact name.
  2. family tells GPU Selector how to start it:
    • zdoom (UZDoom, GZDoom, LZDoom), zdoomrt, prboom, mbf, chocolate, helion, doom64, doomsday
    • plain: only -iwad and -file
    • custom: any program. You list its options in args (see Any game).
  3. "stereo": true: the port has its own 3D. It works for the zdoom and doomsday families (GPU Selector knows how to turn it on), and for a custom port with stereoArgs.
  4. A custom port with 3D: "stereo": true plus "stereoArgs", groups like args with {mode}, {depth} (0-100), {zpd} (0.000-0.250), {swap} (1 or 0), {fov} and {crosshair} (0 to hide it in 3D, 1 to give it back once).
    • "stereoModes": {"sbs": "4", "tab": "11"}: your port's word for each 3D mode ({mode}).
    • "stereoOffArgs": what to send when 3D is off.
    • Without stereoArgs a custom port gets no 3D button.
  5. "label": the exact text in the dropdown (see ports in One mod).
  6. "extraArgs": the words always added for this port, instead of its family's. The ZDoom family adds +vid_preferbackend 0 +queryiwad 0 (OpenGL, no game picker); "extraArgs": ["+queryiwad", "0"] keeps Vulkan. [] adds nothing.

    • Put the file in the card's files folder (see Card packages).
    • GPU Selector checks the SHA256, Windows Security scans it, and the user is asked once before it is used.
    • It only replaces the exact original file (its SHA256) in the card's own copy of the port. That file is kept as keepOriginalAs.
    • Or add a new file next to the port's program: {"file","sha256","adds"} (like the DOOM card's 3D crosshair, dinput8.dll).

  1. On the Mods page, rows that can mix have an M left of their buttons, under 3D.

Your card, your rules

  1. Everything you set in your card (mix, options, text, engine, tabs, ui.colors, ui.order) only changes your card.
  2. You pick almost everything: words, hover tips, colours, the order of parts, where buttons go. What stays with GPU Selector: safety checks, and what only it can know (what is installed on this PC).
  3. Each card keeps its own saved choices: mixes, picks, the Parental Settings answer, the font switch.
  4. A card can never change another card. It can offer GPU Selector's theme (ui.appTheme), but only the user turns it on.

Card packages (.zip) and files

  1. A card can bring files: a port fix (DLL) or its font.
  2. Put them in a folder next to the card named <card file name>_files: doom_card.json + doom_card_files\.
  3. Zip the card and that folder together: doom_card_package.zip (a .7z works too). People load it with Load from File, or with Load from URL and a link to the package.
  4. Load from URL asks "Are you sure this is safe?" first, for every card from a link. A package is scanned by Windows Security before it is opened.
  5. The zip is 256 MB or less, and Windows Security scans it.
  6. Each file is checked by the SHA256 the card gives.
  7. A zip with a program file (DLL, EXE) always shows a warning first. Cards can't turn this off.
  8. Cards on the House only loads cards from the GPU-Selector-Cards site that match their SHA256.

Rules

  1. Only link files you may share. Link the page when a site makes download links per click (itch.io, ModDB).
  2. Files with a SHA256 (from the card or from GitHub) are checked. Other files: GPU Selector asks first.
  3. Windows Security scans every download up to 50 MB before it is unpacked.
  4. A mod download with a DLL, EXE or script always asks the user first ("This Download Has a DLL").
  5. Mods unpack into the card's own folder. Nothing is copied into a game folder.
  6. The page never sends a command line. GPU Selector builds it from checked paths and the port's family.

Your card's guide: "ui.guide"

  1. Write a Markdown file, like GUIDE.md, and put it in your card's files folder (see Card packages).
  2. In the card: "ui": {"guide": {"file": "GUIDE.md", "sha256": "..."}}. Get the SHA256 with Get-FileHash GUIDE.md in PowerShell.
  3. A Guide button shows at the bottom of your card. It opens your guide in the browser, in your card's colour and font.
  4. Pick where the button goes with "position": "left" (the default, after your card's buttons) or "right" (next to "Card by").
  5. What works: # headings (3 sizes), numbered lists, - lists, > tip boxes, **bold**, `code`, --- lines, and https links. Nothing else runs: no pictures, no scripts.
  6. Rename the button with "ui": {"labels": {"guide": "Manual"}}.
  7. 200 KB or less. Update its sha256 every time you change the file.
  8. GPU Selector reads the guide from your card's files folder: next to the .json on your PC, or inside your card package (.zip). From a link or Cards on the House, use a package. If the file can't be found, GPU Selector tells you. The same goes for ui.font.

Write a guide that is easy to follow

  1. Start with a 1-line short version, then 3 steps that get people playing.
  2. One idea per line. Short sentences. Simple words.
  3. Number every step. Put button names in bold, exactly as they read on the card.
  4. Use headings so people can jump to what they need. Use tip boxes (>) for the one thing to remember.
  5. End with "Something went wrong?": each problem in bold, and its fix.
  6. A little flavour from your game is fun (the DOOM card's guide is a "Field Manual"). Keep it light.
  7. No em dashes. No walls of text. Look at the DOOM card's GUIDE.md as an example.

The card's own font: "ui.font"

  1. Best: a font file in the card's package. "font": {"file":"MyFont.woff2","sha256":"...","name":"DOOM","credit":"...","license":"https://..."}.
  2. The file goes in the card's files folder (see Card packages). WOFF2 only, 220 KB or less.
  3. Or put it inside the card: "src":"data:font/woff2;base64,..." (300 KB or less).
  4. name is shown in Options, like DOOM font.
  5. Only free fonts, with their credit and license link.
  6. It only changes this card's headings. The Options page can turn it off.

Making a Card with an AI

The goal: a card brings a project's good features into GPU Selector. It is more than a download button.

Research first

Before making the card, start a separate agent to research the project, in this order:

  1. Is it safe? Its age, makers, license, issues, how its releases are built, and what people report. Not safe? Stop and tell the person. Also find out, from its docs and code:
    • Does it put files in game folders (like a d3d12.dll or dxgi.dll)? That clashes with ReShade and GPU Selector's own DLLs.
    • Does it touch games with anti-cheat? Could someone be banned?
    • Does it start with Windows, send data, or need admin rights?
    Every real risk you find goes on the card: in "notice" for the big ones (bans, broken ReShade), in the text for the rest.
  2. Does it have source code? Then maybe make a simple app from that code, with only the feature GPU Selector needs. Keep the license, credit the author, and publish it in your own GitHub release.
    • Can the whole app become a ReShade add-on? That is a good option too: it then runs inside the game with ReShade, and needs no separate program.
    • Does the project put a DLL into the game (like a d3d12.dll recorder or hook)? Build that part as a ReShade add-on (.addon64) instead. GPU Selector loads it with ReShade through Inject Mode, only in the games the user picks, and nothing stays in the game folder. The card installs it with addons.
    • Can't it be an add-on? A separate DLL that GPU Selector injects next to ReShade is the other way. Cards have no field for that yet: tell the person it is missing.
  3. No simple app? Can the app be driven from outside? Look for start options, a command-line mode, or config files. The card's buttons can use those.
  4. None of that? Make sure the card starts the app properly. Read the app's own docs for the right file, and look inside its zip.

The research decides the card: what it downloads, which file it starts, its buttons, its tabs and its text. Write down what you found, and build the card from that.

Something the card needs but this guide has no field for? Don't work around it. Tell the person which part is missing.

You can ask an AI to make a card. Tell it:

  1. Read this guide.
  2. Read the project's GitHub page, its install guide and its release files. A manager app's GitHub (like RHI) is a good source of the right download links.
  3. Make the card download and install what the project needs. Come up with the tabs and text.
  4. Say if it should turn on in all games or only in certain games.

Checklist for the AI

  1. Links: every download must already exist. Never point to a repo or release that isn't made yet. If the card needs a helper you made, the person publishes it first.
  2. Credits: cardBy is the person making the card, never "AI".
  3. Checking: nothing outside GPU Selector checks a card. Loading it with Load from File is the check: a card with a mistake is not loaded, and GPU Selector says why.
  4. Downloads: use GitHub release files (github + asset, or a releases/download link). They have a SHA256 and get update notices. Avoid github.io and raw links. Other hosts only when the author's own installer uses them, with sha256.
  5. Several products in one repo: pin each with tag.
  6. Names: each add-on's name is its own file name without .addon64.
  7. Where files go: read "besideAddon or nextToGame?" above. Install guides that say "next to the exe" assume the add-on is there. When unsure, use both lists.
  8. Shaders: ship the project's own .fx files with shaders. For LumeniteFX use repoShaders. Never download a shader pack whose author does not allow sharing.
  9. Shader settings: put the values the install guide asks for in preprocessor.
  10. Effect order: GPU Selector can't set it. Write it as numbered steps.
  11. Graphics cards: one tab per brand with "gpu". Say which card series work, from the project's own notes.
  12. Games: an add-on made for some games gets games. Put the same games in targetGames, with notes for game settings, hdr for HDR mods, and reshade locks when the API is known.
  13. Anti-cheat games: add-ons only load offline. Give the game "eacBypass": true and say so in its notes. Online-only games: leave them out. RE Engine games: "reEngineBypass": true.
  14. Text: short numbered lines, one idea per line. No em dashes. Only claims you found in the project's docs or in GPU Selector's own behaviour (like anti-cheat games needing offline mode). When sources disagree, follow the author's newest file (installer payload over an older README).
  15. Test: load it with + Add Mod and Load from File. A card with a mistake shows what is wrong.

The example cards were made this way. Point the AI at GPU-Selector-Cards: it has every example card by level, and AI.md tells an AI where to start.

Check what the AI wrote. Look at every download link before you press Install.

Custom Cards and Card Size

  1. Cards you add go to Custom Cards, away from the built-in cards. Pick Modding Tools with Put them in, in the + Add Mod window.
  2. Open it with the cards button next to Sort in Modding Tools.
  3. To remove a card: its gear button, then Delete. If it installed add-ons or downloads, you pick Keep Them or Remove Them Too.
  4. 625 pixels at most.
  5. A card grows to fit its text, up to 625 pixels. Past that, its description scrolls inside the card with the mouse wheel. The card itself never scrolls.
  6. Long lists, like Target Games, scroll inside their own box (about 2 rows show), with the mouse wheel and no scroll bar.
  7. Cards never scroll sideways. Long words and links wrap.
  8. Tips to fit: short descriptions, a mode switch instead of long lists, and 5 lines or fewer per mode.

📂 EDGE CASE: ZIP Has Extra Parent Folder

Sometimes ZIPs have an extra folder wrapping everything. Handle it!

🤔 Problem: Unwanted Parent Folder

BAD ZIP STRUCTURE                     WHAT YOU WANT
-----------------                     -------------

mymod-v1.0.zip                        Game Folder:
    |                                     +-- dxgi.dll
    +-- mymod-v1.0/     <-- Extra!        +-- config.ini
            |
            +-- dxgi.dll
            +-- config.ini

"installActions": [
    {
        "type": "extract",
        "from": "mymod-v1.0/*",        <-- Include the parent folder name + /*
        "to": "{game}"
    }
]

The /* means "everything INSIDE this folder". The parent folder itself is skipped.

❌ COMMON MISTAKES

❌ WRONG vs ✅ RIGHT

❌ WRONG: Forgetting the /*

"from": "game_files"      <-- Missing /* = copies the folder itself!

✅ RIGHT:

"from": "game_files/*"    <-- With /* = copies contents only

❌ WRONG: Missing quotes in JSON

{from: "files/*", to: {game}}     <-- Keys need quotes!

✅ RIGHT:

{"from": "files/*", "to": "{game}"}

❌ WRONG: Backslashes in paths

"to": "{game}\Data\Textures"      <-- Backslashes break JSON!

✅ RIGHT:

"to": "{game}/Data/Textures"      <-- Always use forward slashes

❌ WRONG: HTTP instead of HTTPS

"url": "http://example.com/mod.zip"   <-- Blocked for security!

✅ RIGHT:

"url": "https://example.com/mod.zip"  <-- HTTPS required

✅ QUICK CHECKLIST BEFORE PUBLISHING

☐ All URLs use HTTPS (not HTTP)
☐ JSON is valid (test at jsonlint.com)
☐ ZIP file downloads correctly
☐ Icon is 128x128 PNG
☐ Background is about 960x480 JPG, under 500 KB
☐ Tested install on your own PC first
☐ Paths use forward slashes: /
☐ "from" paths end with /* for folders

Security Guidelines

For Mod Authors:
  • Always use HTTPS for all URLs
  • Host files on trusted platforms (GitHub, etc.)
  • Don't include harmful code. Files are scanned with Windows Security.
  • Avoid installing to system directories
  • Test your card thoroughly before distribution
Security Features:
  • HTTPS required for all downloads
  • AMSI malware scanning before extraction
  • Blocked system directories (Windows, System32)
  • Path traversal protection
  • JSON-only format (no executable code in card)
  • User warnings before loading external cards

Limits

  • Up to 40 cards you add can be loaded at the same time
  • Each card name must be unique: duplicates are rejected
  • Max 25 target games per card
  • Max 5 install actions at top level, max 5 per target game
  • Max 5 UI elements per type (dropdowns, radios, checkboxes, text inputs)
  • Mode switch: 2 to 12 modes, 4 shown at a time
  • Add-on packages: max 10 downloads, 10 add-ons, 40 files per list
  • Card height: 625 pixels at most. Long lists scroll in their own box
  • versions: ZIP files only. Add-on packages: ZIP, 7z or single files
  • Built-in cards cannot be deleted or edited
